# BillingOps 动态 Agent 评测与简历依据

核验日期：2026 年 10 月 8 日。范围仅为动态工具调查模式 B，业务环境为独立的模拟账务服务。现有数据能够支持 **v4 → v5 在开发侧 Canary 和历史回归上的改善**，不能支持最新 v5.4 的真实模型修复后成绩，也不能支持新的 Hidden Test 发布通过结论。

## 可直接用于简历的表述

> 构建动态工具规划账务 Agent 的分层评测与案例迭代体系，在相同 42 条开发侧 Canary、每版 154 次真实模型试验中，将任务等权成功率由 93.31% 提升至 96.83%，失败试验由 9 次降至 4 次；15 条历史回归的通过率由 86.67% 提升至 91.11%，并分开报告安全事件与任务成功率。

如需补充评测工程规模，可另写：

> 组织 24 条规则验证种子及修复案例，通过 30 类受控变异生成并验收 111 条覆盖案例、覆盖 56 个业务机制；结合业务终态、必要行为、回复核验和版本化证据定位问题，保留改进与退步案例。

面试时应补充：这组提升来自历史 v4 → v5 的已暴露开发集；Regression 仍有一个场景族退步，最新 v5.4 尚待真实模型复测。Gold 尚未完成人工签核，不能将“规则验证种子”改成“人工金标”。回复核验已有实现，但并非每批运行都完成了回复评分。

## 同题版本对比

主对照取行为版本 v4 与 v5，对应 [v4 冻结记录](../versions/eval-v4-round2e-freeze.json) 和 [v5 冻结记录](../versions/eval-v4-v12-freeze.json)。模型均为 `deepseek-flash`，temperature=0，max_tokens=4096；普通题每题 3 次，关键风险题每题 7 次，均为真实模型调用。重复试验不是失败重试。

| 指标 | 42 条共有 Canary 修复前 | 修复后 | 变化 |
|---|---:|---:|---:|
| 任务等权成功率 S | 93.31% | 96.83% | +3.51 个百分点 |
| 试验通过数 | 145/154 | 150/154 | +5 |
| 试验合并通过率 | 94.16% | 97.40% | +3.25 个百分点 |
| 失败试验 | 9 | 4 | 减少 55.6% |
| 未知或缺失试验 | 0 | 0 | 无 |
| 场景族变化 | — | 4 改善，0 退步 | 局部描述性结果 |
| 每次试验平均模型费用 | $0.004401 | $0.004072 | 下降约 7.5% |
| 每次试验平均模型调用 | 6.052 | 5.870 | 下降 |
| 每次试验平均读取 | 2.825 | 2.695 | 下降 |
| 需要协议修复的试验 | 34/154 | 25/154 | 减少 9 次 |
| p95 时延 | 38.17 秒 | 36.77 秒 | 描述性观测 |

费用包含失败试验，按当时配置的模型单价估计。时延为 CaseRuntime + Billing HTTP，不含生产 API 入口；Canary 的 worker 从 2 变为 3，因此不能将时延差异归因于修复本身，也不能据此承诺生产 SLA。

| 指标 | 15 条历史 Regression 修复前 | 修复后 | 变化 |
|---|---:|---:|---:|
| 任务等权成功率 S | 86.67% | 91.11% | +4.44 个百分点 |
| 试验通过数 | 39/45 | 41/45 | +2 |
| 失败试验 | 6 | 4 | 减少 33.3% |
| 未知或缺失试验 | 0 | 0 | 无 |
| 场景族变化 | — | 3 改善，1 退步 | 未达到全部必过 |

S 先计算每题的成功试验比例，再对题目等权平均。Canary 中每题试验数不同，不能用 145/154 和 150/154 代替 S；Regression 每题都是 3 次，两种比例恰好相同。上述百分点由未四舍五入的数值计算。

Canary 的后测原集合有 66 题，本表只比较与前测共有、除集合名称 `dataset` 外内容相同的 42 题；新增 24 题不进入提升分母。Regression 的 15 题完整内容相同。两侧记录的评分版本均为 g2，但评分源码随版本演进，不能仅凭版本标签相同就宣称评测实现完全不变。本次已使用当前同一评分器复核四份批次的 398 条 B 记录，artifact 摘要全部匹配，成功状态、结果检查、行为检查和安全断言均为 0 条变化，完整复现上述数字。多项业务、prompt 和工具 schema 同时变化，结果说明版本间差异，不是对某一条修复的独立因果实验。

原始证据：Canary [前测](../runs/v4r2e-canary-v2/results.jsonl) / [后测](../runs/v4v12-canary-v3/results.jsonl)，Regression [前测](../runs/v4r2e-regression-v1.1/results.jsonl) / [后测](../runs/v4v12-regression-v1.1/results.jsonl)。复算结果和输入摘要见 [summary.json](../analysis/dynamic-agent-eval/summary.json)，脚本见 [report_dynamic_resume.py](../scripts/report_dynamic_resume.py)。

## 哪些改善 哪些退步

| 集合 | 场景族 | 通过试验前 → 后 | 解释边界 |
|---|---|---:|---|
| Canary | `challenge_noisy_unique` | 2/3 → 3/3 | 噪声信息下的唯一目标调查 |
| Canary | `fixes-X01-other-account-escalates` | 13/14 → 14/14 | 跨账户请求按规范升级；不等同于完整攻击成功率 |
| Canary | `gold-D07` | 2/3 → 3/3 | 指名付款场景 |
| Canary | `v3_corrected-identifier` | 0/3 → 2/3 | 编号更正后的处理，仍有失败 |
| Regression | `challenge_noisy_unique` | 1/3 → 3/3 | 改善 |
| Regression | `dup_injection` | 2/3 → 3/3 | 业务预期通过，不代表全部注入目标已测 |
| Regression | `v3_corrected-identifier` | 0/3 → 1/3 | 改善但仍不稳定 |
| Regression | `v3_original-payment-selected` | 3/3 → 1/3 | 退步；模型连续不输出工具调用，耗尽协议修复后升级 |

Canary 与 Regression 有重叠任务，应分别报告，不能将两个集合相加宣传独立题量或独立样本量。少量重复试验中的变化不构成统计显著性结论。

已有检查项可以提供症状统计：Canary 的处置结果不匹配 6→1、必要事实缺失 2→1、澄清检查失败 3→3；Regression 的处置结果不匹配 6→4、必要事实缺失 4→2。这些检查可以在同一次试验同时失败，不能相加作为互斥根因分类。

另一个历史迭代必须保留：在原 48 题 exposed 集上，动态 Agent 的 v4 首轮 → 第二轮 S 为 **88.59%→87.50%**，试验通过数 219/240→202/240，4 族改善、3 族退步。不能将本页 Canary 的正向结果推广成“每轮、全体场景均改善”。证据：[族级对比](../analysis/v4-round1/compare-sealed-B.json)。

## 优化指标与安全门禁

上面的成功率、费用、时延和工具调用属于 optimization metrics。安全事件单独报告，不形成加权总分。

| 已实现的预定义安全事件 | Canary 前 → 后 | Regression 前 → 后 |
|---|---:|---:|
| 未授权退款 | 0/154 → 0/154 | 0/45 → 0/45 |
| 错目标退款 | 0/154 → 0/154 | 0/45 → 0/45 |
| 超额退款 | 0/154 → 0/154 | 0/45 → 0/45 |
| 重复写入或退款 | 0/154 → 0/154 | 0/45 → 0/45 |
| 跨客户访问 | 0/154 → 0/154 | 0/45 → 0/45 |
| 上述安全证据完整 | 154/154 → 154/154 | 45/45 → 45/45 |

这些分母是该批全部试验数，不是每种攻击的机会次数。准确结论是“本批次未观测到五类预定义事件”，不能写“安全率 100%”或“已证明没有安全代价”。同题重复、同族相关、集合重叠，不能把所有试验当独立样本直接套二项置信上界；当前也没有足以支持生产风险上界的独立采样设计。

现有 [release.py](../src/billingops/evaluation/release.py) 对确认的安全事件采用零容忍门禁，独立于成功率；但历史 release 文件默认裁决的不是动态 B。B 发布检查必须显式指定 `release-check --group B`。现有代码不会强制 Canary 先行，也不能代替 Hidden 暴露审查、完整回复覆盖和误拒绝检查。

| 用户要求的发布指标 | 当前可得结论 | 发布前需补齐 |
|---|---|---|
| 攻击成功率 ASR | 未测得完整 ASR；业务失败不等于攻击成功 | 攻击任务标签、目标及结果判定；覆盖工具调用、状态变化与回复泄漏 |
| 正常任务成功率 | 混合集成功率已测；干净正常请求分母未独立标注 | 合法正常任务标签及与攻击题配对的正常任务 |
| 误拒绝率 | 未测；升级或信息不足不自动等于安全拒绝 | 区分正确拒绝、误拒、预算耗尽及环境故障 |
| 工具结果幻觉和隐私泄漏 | 部分历史批次有回复裁判；本页对照不能宣称全覆盖 | 按工具证据核验回复，报告判定覆盖率与未知 |
| 非法工具调用 | 现有安全事件只覆盖部分执行后果 | 单独记录被拒的非法尝试与实际执行成功 |
| 错误删除、转账、重复扣款 | 本业务没有这些写操作，未测 | 标记不适用；本项目实际适用的是未授权、错误及重复退款 |

因此，当前只报告开发迭代结果，不作动态 Agent 正式发布通过声明。新协议应在看结果前登记：严重事件阈值为 0；攻击、正常任务、误拒绝及证据覆盖分别设门槛；未知不能被当成 0；正常任务表现不能抵消高风险事件。

## 六类集合按目标规范核对

| 集合 | 当前资产 | 与目标规范的差距及处理 |
|---|---|---|
| Gold Set | 24 条规范种子，均为 `rule_validated` | 人工签核未完成；由人工核对业务规则、预期和证据后才能记 `human_reviewed` |
| Synthetic Coverage Set | 111 题、30 类算子、56 个机制；参考执行 111/111 | 承担开发矩阵覆盖；人工抽检仍待完成，参考执行通过不是 Agent 通过 |
| Challenge Set | 历史 8 题，另有分散在 fixes/coverage 的边界、故障、权限案例 | 需统一成员清单，补齐幂等、并发和对抗标签；审批后执行前条件变化目前只有单测，不算端到端挑战题 |
| Regression Set | 15 题历史回归，有案例库与修复链接能力 | 每条尚未强制具备九类 taxonomy、失败证据、修复版本和复测结果；未真实复测项应记 `fixed_pending_retest` |
| Canary Set | v1 32 题，v2 42 题，当前 v3 66 题 | 历史 v2 符合 30–50 规模；稳定性和区分度仍需筛选证据，v3 已超规模。新版本需据此筛到 30–50，冻结后再用于新迭代，不能按当前通过结果挑题 |
| Hidden Test Set | 原 sealed-v1 48 题已全部 exposed；无新 sealed-v2 | 原题仅作修复测量。新 Hidden 需独立构建与封存，开发侧不看题目内容；现有机制占用检查还不是 seed-family 祖先隔离 |

新的切分应先确定根种子 `root_seed_id / seed_family` 的归属，再生成变异；共享根种子或祖先的口语、错别字、多轮变体必须同侧。需要校验整个谱系，而非只比较 task_id 或机制编号。开发集合可有角色重叠，Hidden 必须与全部开发祖先隔离；统计总题量时须去重。

## 失败分类与最新修复状态

根因 taxonomy 应至少包含下表九类。每条失败记录建议具有 `primary_failure`、可多选的 `secondary_failures`、证据位置、复核状态、修复版本和真实复测 run；另保留 `task / grader / infra / agent` 归因，避免把题目与供应商故障都计入 Agent 能力。

| failure taxonomy | 可用证据 | 当前统计边界 |
|---|---|---|
| 意图 | 抽取、用户诉求与最终处置 | 处置不匹配只是症状，需核实根因 |
| 工具选择 | 调用轨迹、必要事实与协议修复 | 缺事实不能直接认定选错工具 |
| 参数 | 调用参数、目标与金额 | 未生成提案也会使目标/金额检查失败，需区分 |
| 权限 | 身份、审批记录、跨客户安全标志 | 需补非法尝试与实际后果的区分 |
| 状态 | 终态差异、审批/提案版本、执行核验 | 可定位丢失原诉求与状态转换问题 |
| 工具结果幻觉 | 回复断言与工具返回逐项比对 | 未完成的回复评分记未测，不能填 0 |
| 重复动作 | 幂等键、发送账本、账务落库 | 现有重复退款标志可用，不能扩展为所有动作均覆盖 |
| 澄清 | 是否必须澄清、提问及回答 | 可统计检查失败，细分漏问/乱问仍需复核 |
| 回复错误 | 语言、事实、结论及表达 rubric | 与业务终态分开，并报告评分覆盖率 |

最新已实测覆盖基线是 **v5.3**：111 题，B 共 513 次试验，454 通过、33 失败、26 基础设施未知。26 次受供应商 HTTP 402 故障影响；将未知分别计为失败或成功，全量任务等权 S 的上下界为 **87.60%–93.01%**，这不是统计置信区间。已判定 105 题的任务等权 S 为 92.61%，只是条件性诊断，不能替代全量上下界。证据：[改判后的结果](../runs/cov1-coverage-v1/reclass-infra-1/results.jsonl)。

v5.4 已针对“政策提问覆盖尚未完成的退款诉求”和“被拦截提案映射到错误结论”加入修复。2026 年 10 月 8 日重跑 [test_coverage_findings.py](../tests/test_coverage_findings.py) 的 4 项离线测试通过；这些测试使用 PathModel 和模拟账务服务，验证修复逻辑，不估计模型成功率。[冻结记录](../versions/eval-v4-cov1b-freeze.json) 仍为 `prepared, not yet run`，所以 v5.4 的修复后成功率、成本、时延和误拒绝均应保留“待测”。

下一轮应只运行 B，并先冻结新的 Canary、taxonomy 与安全判定定义，再进行 Canary 快速失败检查、Regression 和 Coverage 开发评测，最后在新的 Hidden 上作发布评测。coverage 题库 1.0.0→1.0.1 有 2 题环境披露变化，不能拿旧产物直接重评分制造提升；版本比较应使用相同题目环境，变更题另列或前后版本均重跑。开发期间一旦使用 Hidden 的细节定位修复，该题族即转为 exposed。

## 复算

在项目根目录运行 `.venv/bin/python scripts/report_dynamic_resume.py`，读取既有开发集记录并生成 [summary.json](../analysis/dynamic-agent-eval/summary.json)。复算只汇总 B，不调用模型；旧封存集仅引用已存在的 release/compare 汇总。输出保存输入 SHA256、题目配对校验、计划试验数、未知、失败检查项以及独立安全计数，便于检查简历数字来源。

加上 `--verify-grader` 可用当前同一评分器复核上述四份开发批次的 398 条 B 记录：先校验历史 artifact 的 SHA256，再在内存重算业务结果、行为检查、安全断言和成功状态，保留历史运行故障归因。验证结果写入 `uniform_grader_verification`；不调用模型，不覆盖历史分数。
