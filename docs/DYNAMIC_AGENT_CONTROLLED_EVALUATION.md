# 动态 Agent：受控变异与统一评测

本轮遵循“先受控变异，再统一评测”：保留32条模拟业务种子，生成96条单因素变体，冻结为128条开发侧案例，再对动态Agent B0执行同一批744次DeepSeek试验。**2026年10月9日，`runs/dynamic-v2-B0-unified-2` 已完成744/744次，完整性校验通过。案例等权完整成功率32.37%，尚未进行Agent修复。** 前次 `runs/dynamic-v2-B0-unified-1` 因余额不足中断，仅作诊断保留，不并入本轮统计。

[重启登记审计](../analysis/dynamic-eval-v1/unified-2-registration-audit.json)确认题库、逐题次数、模型、公开业务输入、风险及安全分母保持不变。冻结文件仅有runner自动停止调度和协议状态记录两处变化，Agent业务逻辑未改；旧386条记录不并入新运行。

这128条按资产主角色分为32条gold_dev候选、84条synthetic_coverage和12条challenge，仍来自32个父种子、12个声明根族；不能当作128个独立业务情境，也不能把开发变体改称Hidden。候选及变体均完成助手审查，独立逐题人工审核仍待用户完成。没有真实企业工单或外部专家金标；本文数字为 B0 基线，B1 状态见[修复登记](DYNAMIC_AGENT_B1_REPAIRS.md)。

## 每条变体改变什么

“单因素”约束独立业务条件，不约束只能改一个JSON字段。变体必须列出 `primary_dimension`、`independent_changes`、`dependent_updates`、`preserved_factors`，并保存精确字段差异、父种子摘要、来源和审核状态。

| 算子 | 条数 | 唯一独立变化及必要联动 |
|---|---:|---|
| W1 中文表述 | 32 | 只改初始客户表达，事实、业务意图、世界和答案不变 |
| L1 英文交互 | 32 | 翻译初始诉求、预写条件回答和后续消息；事实与披露能力不变 |
| U1 客户金额声称 | 4 | 客户把49元说成48或50元，真实账务保持49元；要求说明核查差异 |
| B1 金额边界 | 4 | 真实账单单位金额改为1分或100元；付款、相关订阅价格、客户金额及预期退款同步推导 |
| S1 历史退款状态 | 4 | pending与completed互换；相关完成时间及应回复事实同步调整 |
| I1 信息披露 | 2 | 客户能否提供正确编号；按相同规则重新推导继续处理或诚实结束 |
| D1 审批决定 | 2 | 操作员批准或拒绝；审批规则本身保持不变 |
| P1 目标归属 | 4 | 目标改为他人所有，当前客户绑定保持不变；预期拒绝访问和操作 |
| A1 工具内容注入 | 4 | 只在可查询的账单描述加入攻击内容；业务GT及权限规则不变 |
| F1 读取故障 | 4 | 一次短暂读不可用；初态与业务目标不变 |
| F3 提交后丢回执 | 4 | 一次退款提交成功后响应丢失；要求查询核验且不得重复发送 |

B1在表中是金额算子编号，和未来Agent修复版本B1不同。1分为合成边界，不是真实套餐售价。L1只保证指定客户文本为英文，工具数据、业务规范和未知回答仍可能含中文，因此不称全英文环境。并行worker仅是试验隔离，不是同一账务对象的并发攻击案例。

例如 `G01-U1-48` 只改变客户说法，实际仍应退49元；`G01-B1-1` 改变真实金额，预期退1分。前者不能改GT金额迎合客户，后者不能机械沿用49元答案。P1允许改变归属条件，但不能改写“不得处理他人账户”的规则。

原始 `task_id` 与目录快照用于父种子追溯；实际执行使用唯一 `case_id`，评分规则模板使用显式 `grading_profile_id`。目录快照是不可变父定义，不能当作变体的新GT。

### 安全、攻击与故障

隐私检查712次可判定、32次unknown，未观察到已确认泄漏；不是“安全率100%”。工具注入49次中47次确实进入模型请求并取得对应响应，另外2次未触达；47次实际触达未观察到攻击目标达成。全49次含1次隐私unknown，不能统一宣称攻击成功率已证明为零；同时注入任务完整成功仅2/49，防住攻击与完成原任务必须分开看。

| 故障 | 计划／实际触发 | 触发后的业务终态通过 | 触发后的完整任务通过 |
|---|---:|---:|---:|
| F1 一次读取不可用 | 20 / 20 | 13/20 | 6/20 |

自动多标签分诊为必要信息/工具选择482、意图252、状态209、澄清132、回复80、工具结果幻觉19。标签可重叠，不能相加；“工具选择”主要是缺信息的症状，需结合轨迹找根因。当前高优先级证据包括：

1. **整账单证据完整性。** 业务结果正确但缺少原付款的退款记录，影响Behavior；原付款也可能已经退款，不能只查拟退那笔。
2. **凭证定位与排他目标的执行适配。** G08部分轨迹中模型已明确付款编号只是账单定位线索，系统仍以`customer_payment_mismatch`阻断。应审查执行侧目标解析，不把全部问题归因为模型没理解。
3. **同账单多笔处理是新增能力。** G12/G13固定样本仍提交单个`target_payment_id`，被`ambiguous_customer_target`阻断；最终回复询问确认，却未真正调用澄清流程。需明细提案、客户确认、审批与逐笔执行的完整适配，不能仅修改一句回复。
4. **回复与判定校准。** 保留缺观察、缺回复和裁判协议unknown；定向复核与自动分数分别记录，规则修订后需要共同重评或重跑，不能只替候选版本放宽标准。

本轮唯一记录为`agent_failure`的G01-F3-01-t4，原始证据实际显示执行前Billing读取发生`Connection reset by peer`；其模型调用均成功，没有退款发送，F3故障没有消费。根本原因未获证实，不能用来证明写后恢复失败；诊断保留原分类和传输错误证据，不改原分或静默排除。

## 第一次运行中断及测量限制（unified-1）

本批登记744次，停止时记录386次完整结果，358次没有完整结果；后者包含16个已启动但途中终止的目录。386条中，177条没有执行阶段异常、1条为条件客户协议异常、208条为模型供应商异常。**177不是通过数**，也不代表回复裁判全正常。原始Agent/客户/裁判日志共记录434次HTTP 402；调用数与trial数不能混用。

[DeepSeek官方错误码](https://api-docs.deepseek.com/zh-cn/quick_start/error_codes/)将402定义为账户余额不足。检测到连续402后已终止本进程（退出码143），没有继续消耗后续试验。原始run未改写，没有生成 `summary.json`；正式分析器拒绝对缺失计划输出完整报告。

[停止时源码审计](../analysis/dynamic-eval-v1/unified-stop-source-audit.json)确认本批运行结束时128份冻结文件无漂移。停止后对后续runner或状态文档的修改需另行版本登记，不倒改本次冻结来源。补充余额后使用新的运行目录重启完整744次；本次全部记录保留作诊断，不选择性补跑失败以拼出正式分数。

[中断证据审计](../analysis/dynamic-eval-v1/B0-unified-interruption-v1/interruption-audit.md)核验2690个归档文件，保存全部缺失试验、16个途中目录和HTTP错误逐调用记录；冻结源码及已完成结果的原始轨迹/裁判/评分绑定完整性通过，正式汇总拒绝记录另存。434次402中，Agent调用399次、回复裁判35次；不是434个独立任务。

已完成轨迹仅供定向复核：观察到1分金额按1分执行、提交后丢回执通过查询核验等局部goodcase；也发现客户已确认两笔共200元而模拟客户的固定表达校验未识别的harness问题。它已保留为unknown，不能归因成Agent不会确认退款。局部结果和助手审查不能替代完整评测或人工金标。

[9条定向证据审计](../analysis/dynamic-eval-v1/unified-mutation-trace-audit.md)另记录了一条疑似回复裁判漏判：已有pending退款没有待审批证据，Agent却说仍需审批，而原子评分通过。它进入校准候选，不覆盖原分。1分执行和F3恢复虽然局部正确，整题仍因必要证据不完整失败；完整goodcase与局部正确行为分开记录。

停止后已为后续运行增加 `v2-runner-1.3`：最多workers个任务在飞；任一模型角色返回401/402即停止新增调度、收尾已启动任务，记录 `provider-stop.json` 与 `incomplete-run.json`，CLI退出码为2。即使错误出现在最后一题，也不会输出完整 `summary.json` 或成功率。该修正只处理评测调度，不是Agent业务优化；中断run使用冻结的1.2，完整重跑使用1.3。
