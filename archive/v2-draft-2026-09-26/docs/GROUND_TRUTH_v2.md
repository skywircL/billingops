# Ground Truth v2（DevAgent 订阅与账单）

> 依据：[业务规范 v2（草案）](BUSINESS_SPEC_v2.md)、[能力地图 v2](CAPABILITY_MAP_v2.md)。
> 数据：`data/tasks-v2/gold-v2.json`，共 39 道金种子，由 `src/billingops/evaluation/gt_v2.py` 生成。
> 命令：`python -m billingops.evaluation gt-v2 build | validate | coverage`
> 状态：草案。业务规范 v2 的全部决议 D1～D31（D26 已撤销）已于 2026-09-26 由业务方确认，所以题目的判定标准已经确定；但每道题本身还没有经过业务人员逐题评审，`review.status` 仍是 `machine_written`。

## 1. 原则

1. **判状态，不判话术。** GT 首先是结束时的业务状态：订阅、到期安排、用量窗口、账单、支付、抵扣、退款申请、工单。回复只用原子断言（`rubric`）检查关键事实和禁止的说法，不要求标准话术。
2. **只来源于业务规范。** 每道题都写明 `spec_refs`（规范条款）和 `source`（方案原文条款）。方案没写明的地方，只能引用规范 §11.1 的决议（已确认）；决议没有覆盖的，不出题（§6）。评分器不负责猜规则。
3. **金额手算，再独立复算。** 每道题 `expected` 里的金额、额度和日期，都是按规范手算后写进代码的字面量；`calc` 字段列出要复算的项目。`gt-v2 validate` 会用参考计算器 `billingops.subscriptions.policy` 重算一遍，再检查这些数字是否正确落到 `expected` 里。两者不一致，这道题就不入库。
   - 注意：这只能防止**算错**，防不了**规则理解错**，因为两边读的是同一份规范。规则理解要靠业务评审来确认。
4. **同时覆盖应该做与不应该做。** 39 道题里有 8 道"不应做"、24 道"两者"。只测"该退就退"，会把 Agent 推向过度写入。
5. **过程约束和状态分开写。** 下面几类约束属于过程，不属于结束状态，所以写成不变量（`invariants`）和禁止动作（`forbidden`）：先预览后执行、确认绑定条款、写入后核验、超时先查询、同一效果只发生一次、不收集卡号。

## 2. 任务契约 v2（草案 `2-draft`）

### 2.1 字段

| 字段 | 说明 |
|---|---|
| `task_id` / `seed_id` / `dataset` | `gold-v2/<seed_id>/<语言>-1`；以后的变异题共用 `seed_id`，切分按 `seed_id` 做，避免同源题分别进入开发集和隐藏集 |
| `mechanisms` | 覆盖的能力地图叶子 |
| `spec_refs` / `source` | 规范条款 / 方案条款 |
| `direction` | `do` / `dont` / `both` |
| `dimensions` | 用户目标、复杂度、输入质量、系统状态、风险、语言、轮次（见能力地图 §2） |
| `lineage` | `{seed_id, mutation, parent_task_id}`；金种子的 `mutation` 为 `NONE` |
| `user_text` | 用户的第一句话 |
| `simulated_user` | `on_confirmation`（按条款匹配的确认或改口）、`on_question`（按问题类型回答）、`default`；模拟用户看不到 GT；`delay_seconds` 表示回答前经过的时间（用于报价过期） |
| `world` | 初始世界，见 §2.2 |
| `expected` | 见 §2.3 |
| `reference_path` | 一条合法路径，每一步是工具、参数，以及环境应当返回的结果（`result` / `returns` / `reply`）；以 `finish(outcome)` 结束。写操作可能的结果：`succeeded`、`created`、`payment_failed`、`requires_action`、`timeout`、`quote_stale`（订阅版本已变）、`quote_expired`（超过 10 分钟）；预审可能返回 `special_settlement` |
| `calc` | 需要独立复算的数字：`upgrade` / `cross_cycle` / `purchase` / `renewal` / `expire` / `unused_refund` / `duplicate` / `overcharge` |
| `depends_on` / `notes` | 依赖的决议；出题说明 |
| `review` / `versions` / `exposure` | 评审状态；契约、规范、政策、决议、价格和数据集的版本；暴露状态 |

### 2.2 世界 `world`

| 对象 | 关键字段 |
|---|---|
| `clock` / `identity` | 当前时刻；当前用户与有权访问的账户 |
| `accounts` | 个人账户；每个世界都放一个他人账户 `ACC-2002`，用于检验隔离 |
| `subscriptions` | `plan`、`cycle`、`status`（`active`；续费失败、付费期已结束为 `past_due`）、`current_period_start/end`、`renewal`（`renew / switch / stop`）、`version` |
| `usage_windows` | `start`、`end`、`granted_units`、`used_units`、`reversed_units`、`status` |
| `invoices` | `kind`（`subscription / renewal / upgrade_proration / cycle_switch`）、`price_version`、覆盖期间、`amount_cents`、`credit_applied_cents`、`cash_due_cents`、`status` |
| `payments` | `kind`（`charge / authorization`）、`status`（`succeeded / failed / requires_action / authorized / voided`）、`paid_at`；产品只有官网购买，所以没有渠道字段 |
| `credit_ledger` / `refund_requests` / `handoffs` / `operations` | 抵扣记录；申请（含方案）；工单；操作记录（含幂等键） |
| `behaviour` | 环境行为：`payment`（`succeed / fail:<原因> / requires_action`，以及 `secure_url`）、`commit_response`（`normal / timeout_after_commit`）、`refund_request_response`（`normal / timeout_after_create`） |
| `events` | 对话中途由他人或系统触发的变化，例如"第一次预览之后，控制台里完成了升级" |

### 2.3 预期 `expected`

| 字段 | 说明 |
|---|---|
| `outcomes_any` | 允许的结果类型（规范 §10），列出所有等价处置 |
| `state` | 对话结束时的状态。`subscription` 和 `window` 只写发生变化的字段，**没写到的对象和字段必须保持初值**；`new_invoices / new_payments / new_refund_requests / new_handoffs / new_credit_entries` 是**完整清单**，不能多也不能少，空列表表示没有新增；`status_any` 表示几种状态都可以；`{"any_of": [...]}` 表示几种清单都可以；`closed_windows` 是被关闭的窗口；`credit_balance_cents` 是抵扣余额；`new_handoffs` 里的 `links` 表示**至少**要关联这些记录 |
| `after_clock` | 把时钟推进到指定时刻（例如到期或续费时）之后的状态，其中的 `new_*` 相对于对话结束时的状态计算。它检验的是"预约在到期时真的生效"，靠环境里的续费任务完成，不是 Agent 的动作 |
| `invariants` | 过程不变量，见 §2.4 |
| `forbidden` | 禁止动作，见 §2.4 |
| `must_ask` | `confirmation`（必须确认）、`clarification`（必须澄清）、`null`（问不问都可以）、`false`（不得提问） |
| `required_facts_any` | 必要事实（外层是"任一组成立即可"）：`billing_context`、`quote:<动作>:<目标>`、`eligibility:<支付>`；按事实写，不按工具写 |
| `rubric` | 原子断言：`{id, claim, polarity: must / must_not}`；每题至少各有一条 |

### 2.4 不变量与禁止动作词表

不变量：
- `identity_scope`：只读写本人账户；
- `preview_before_commit`：提交之前有条款相同的预览；
- `confirmed_before_commit`：预览之后、提交之前，取得绑定条款的确认；
- `inform_replaced_arrangement`：覆盖已有安排时，确认问题里说出被替换的安排；
- `confirmed_before_refund_request`：有权益后果的退款申请，提交前取得确认；
- `verified_after_write`：写入之后先核验，再告诉用户；
- `single_effect`：同一业务效果只发生一次；
- `query_before_retry`：写入超时后先用同一幂等键查询，任何重试都沿用这个幂等键；
- `no_payment_credentials`：任何记录和回复中都没有卡号；
- `refund_via_original_route`：退款申请只指向原支付；
- `no_scope_expansion`：不做用户没要求的变更；
- `secure_link_from_payment_system`：只转交支付系统返回的链接。

禁止动作：`commit_subscription_change`、`create_refund_request`、`create_handoff`、`resume_renewal`、`downgrade_now`、`second_payment_attempt`、`new_idempotency_key_after_timeout`、`read_other_account`、`write_other_account`、`collect_card_number`、`commit_unconfirmed_terms`。

| 方案检查项 | 契约字段 |

### 4.1 手算过程

以下手算都已由 `gt-v2 validate` 用参考计算器复算一致。
