# DevAgent 订阅与账单业务方案

> **政策版本：** `subscription_policy_v1`  
> **文档状态：** 业务讨论稿，待确认后用于实现与评测  
> **产品定位：** AI 编程助手及其订阅客服 Agent  
> **设计参考：** Codex／Claude Code 所属付费套餐的分层方式，不直接复制其官方价格、权益或退款条款。

本文归纳本项目的套餐、订阅变更、退款、异常处理、工具权限和评测方案。所有项目价格、额度、期限与处置规则均为建议配置；金额示例不考虑税费、折扣和汇率变化，正式执行以经批准的业务政策和计费系统为准。

## 1. 项目范围与核心原则

### 1.1 首版范围

首版支持个人账户、官网直接购买、美元结算，以及以下能力：

- 套餐、额度、账单和订阅状态查询。
- 购买、立即升级、预约降级、计费周期切换、取消与恢复续费、撤销预约。
- 退款资格预审、申请提交、人工审批和进度查询。
- 付款失败、接口超时、重复提交、权益未到账等异常恢复。

首版不支持团队席位、企业合同、加量包、自动充值、超额自动扣款和直接修改第三方渠道订阅。相关请求应说明边界，按需引导或升级人工。

### 1.2 核心原则

| 原则 | 要求 |
|---|---|
| 先预览，再执行 | 展示费用、额度、权益、生效时间和续费安排，取得有效授权后执行。 |
| 以业务状态为准 | 支付、订阅和权益需要分别核验，不能仅凭接口成功或一句回复判断完成。 |
| 资金概念分离 | 使用额度、订阅费抵扣余额和现金退款分别记录，不能相互混用。 |
| 退款审批隔离 | Agent 可以预审与提交申请，不能自行批准或直接执行退款。 |
| 约束由后端实施 | 账户权限、报价有效性、退款额度和幂等性不能只依赖提示词。 |
| 不擅自扩大授权 | 用户同意升级，不等于同意恢复续费；用户申请退款，不等于立即同意降级。 |

## 2. 套餐与用量规则

### 2.1 套餐配置

| 套餐 | 月付 | 年付 | 每个完整月度用量窗口额度 | 同时运行任务数 | 主要权益 |
|---|---:|---:|---:|---:|---|
| Free | $0 | — | 50 单位 | 1 | 基础问答、代码解释和体验任务。 |
| Pro | $20 | $200 | 1,000 单位 | 2 | 编程任务、CLI／IDE 使用、代码修改与审查。 |
| Max 5x | $100 | 暂不提供 | 5,000 单位 | 5 | Pro 权益，更高额度与并发。 |
| Max 20x | $200 | 暂不提供 | 20,000 单位 | 10 | Pro 权益，更高额度与并发。 |

“5x／20x”只表示相对 Pro 的完整月度额度倍数，不表示速度、质量或全部性能指标的倍数。价格、额度和并发数是测试与业务设计配置，商业化前需要进行成本校准。

### 2.2 用量规则

| 项目 | 规则 |
|---|---|
| 计量单位 | 使用内部 `usage_unit`，由用量服务计量，不直接等同于消息条数或现金。 |
| 多端共享 | 网页、CLI、IDE 共用同一账户额度。 |
| 年付发放 | 一次支付全年费用，额度按月发放。 |
| 结转 | 当前窗口未使用额度到期失效，不结转。 |
| 额度用尽 | 暂停新的付费任务，可等待重置或升级；不自动产生超额费用。 |
| 错误计费 | 平台故障造成的错误消耗由用量服务冲正，保留原始记录与冲正记录。 |
| 结果不满意 | 不自动视为未使用，按服务或退款政策处理。 |

## 3. 订阅变更规则

### 3.1 变更矩阵

| 请求 | 生效时间 | 资金处理 | 目标状态 |
|---|---|---|---|
| Free → 付费套餐 | 新账单结算后 | 收取所选周期费用。 | 开通目标套餐与额度。 |
| Pro 月付 → Max 月付 | 差价账单结算后立即生效 | 按剩余账期补差。 | 升级套餐，保留原账期。 |
| Max 5x → Max 20x | 同上 | 按剩余账期补差。 | 升级套餐，补发对应额度。 |
| Max → 较低月付套餐 | 当前账期结束后 | 本期不自动退款，下期按新价收费。 | 当前套餐不变，记录预约降级。 |
| Pro 月付 → Pro 年付 | 新账单结算后立即生效 | 剩余月费价值抵扣年费。 | 开始新的年度计费周期。 |
| Pro 年付 → Pro 月付 | 当前年度结束后 | 不自动退还未到期年费。 | 记录到期切换安排。 |
| Pro 年付 → Max 月付 | 新账单结算后立即生效 | 未履约年费价值抵扣新套餐费用。 | 开始新的月度计费周期。 |
| Max 月付 → Pro 年付 | 当前月度账期结束后 | 届时结算 Pro 年费。 | 预约降级并切换周期。 |
| 取消订阅 | 立即停止续费安排，权益到期终止 | 不自动退款。 | 当前付费权益保留到期。 |
| 到期前恢复续费 | 用户确认后 | 不重复收取本期费用。 | 恢复指定套餐的续费安排。 |
| 撤销预约变更 | 预约尚未生效时 | 不收费。 | 清除对应预约，保留当前套餐。 |
| 到期后重新订阅 | 新账单结算后 | 按新购买收费。 | 开始新的付费周期。 |

“结算”包括现金支付成功或合法抵扣足额覆盖，不能把零现金应付误判为付款失败。

### 3.2 月付升级：按剩余时间补费用和额度

```text
升级补款 =（目标月费 − 当前月费）× 账期剩余比例
新增额度 =（目标月额度 − 当前月额度）× 用量窗口剩余比例
升级后可用额度 = 原可用额度 + 新增额度
```

账期比例和用量比例分别取对应窗口的实际起止时间。金额与额度的计算、舍入由后台统一实施，Agent 读取结果，不自行决定最终数值。

**示例：Pro 月付升级 Max 5x。** 假设账期和用量窗口均为 30 天、剩余 15 天，Pro 已使用 900 单位。

| 项目 | 结果 |
|---|---:|
| 本次补款 | `(100 − 20) × 50% = $40` |
| 新增额度 | `(5,000 − 1,000) × 50% = 2,000` |
| 本窗口累计发放 | 3,000 单位 |
| 本窗口累计使用 | 900 单位，不清零 |
| 升级后可用额度 | 2,100 单位 |
| 下个完整窗口额度 | 5,000 单位 |

付款失败时不改变原套餐、不补发额度。不能只补半个月费用，却直接发放完整新套餐额度。

### 3.3 立即跨周期变更：关闭旧周期，开启新周期

适用于 Pro 月付转年付，以及 Pro 年付升级 Max 月付。

旧订阅未履约部分的价值由计费系统核定，用于抵扣新订阅费用。变更完成后开启新计费周期，关闭旧用量窗口，按新套餐发放新窗口额度；旧用量记录仍保留用于对账和退款审核。剩余抵扣价值记入订阅费抵扣账本，不自动现金退款。

| 示例 | 结算结果 |
|---|---|
| Pro 月付转年付，月费 $20，剩余一半账期 | 抵扣 $10，新年费 $200，本次应付 $190。 |
| Pro 年付升级 Max 5x，系统核定剩余价值 $150 | 新月费 $100 全额抵扣，剩余 $50 留作后续订阅费抵扣；现金扣款与现金退款均为 $0。 |

该规则属于本项目提案。上线前需确认跨周期频繁切换的限制，避免反复重开窗口造成非预期额度收益。

### 3.4 预约冲突与授权

同一订阅最多保留一个明确的到期处理安排：原套餐续费、切换套餐或停止续费。

新安排覆盖旧安排前必须明确告知用户。例如，取消订阅将替换已有的下期降级预约。已取消续费的用户只要求升级本期剩余时间时，不得默认恢复续费。

用户说“只有能退款，我才同意立即降级”，应按有条件的组合请求处理；退款方案未获批准前，保持原套餐与权益。

## 4. 退款政策与处理流程

### 4.1 退款政策矩阵

下表中的“7 天”为本项目拟定的自愿退款窗口，不是对任何地区法定期限的认定。正式上线前须按经营地区、购买渠道和合同要求审查；适用的强制性要求优先于默认政策。

| 场景 | 拟定政策 | Agent 处置 |
|---|---|---|
| 购买后 7 天内，未使用该次购买覆盖的付费服务 | 可申请退还该笔尚未退回的实付金额。 | 查询支付与用量，预审后提交人工审批。 |
| 自动续费后 7 天内，新周期未使用 | 按未使用规则审核。 | 核验新周期用量；停止续费需有相应授权。 |
| 已使用，仅因不想继续使用申请退款 | 不适用常规未使用全额退款。 | 解释政策，可办理取消续费；其他理由另行审核。 |
| 超过 7 天 | 不适用常规未使用窗口，不代表所有退款理由都被排除。 | 检查计费错误、服务故障及其他适用情形。 |
| 重复扣款 | 核实后退还重复收取部分。 | 核对实际成功支付，不将预授权误判为重复收费。 |
| 错误收费或超收 | 退还核实后的超收部分。 | 关联报价、账单与支付记录，提交部分退款申请。 |
| 平台故障导致付费服务不可用 | 按已批准的故障补偿政策处理。 | 收集故障记录与受影响范围，交人工核定。 |
| 已升级、已抵扣或已部分退款 | 专项结算，避免同一价值重复退还。 | 查询关联资金记录后交人工审核。 |
| 支付争议或疑似盗刷 | 进入支付争议或安全流程。 | 不直接走普通退款出款流程。 |
| 第三方渠道购买 | 按渠道权限处理。 | 识别渠道并引导，不能声称已在官网系统退款。 |

退款窗口以申请被系统接收的时间判断，不因人工审核耗时而失效。用量在申请时及执行前复核；申请后继续使用导致资格变化时，应告知用户并重新审核。

### 4.2 退款不等于取消或降级

| 退款类型 | 订阅与权益处理 |
|---|---|
| 普通全额退款 | 用户确认权益后果，获批并进入执行时，终止该笔款项覆盖的权益及对应续费；仅提交申请不立即收回权益。 |
| 重复扣款退款 | 只退重复支付，合法购买形成的订阅继续有效。 |
| 部分退款 | 默认只调整资金；只有批准方案明确要求时才调整套餐或权益。 |
| 退款执行失败 | 保留应退责任、原申请和失败记录，交人工处理，不能伪装成退款完成。 |

每份审批方案必须明确：**原支付、退款金额、权益处理、生效时间、是否停止续费**。不能只保留一个批准布尔值。

### 4.3 资金约束与状态

现金退款不得超过原支付尚可退还的现金余额。已成功及处理中退款均占用可退额度；关联抵扣已经使用或转移时，必须做专项结算。退款通过支付系统原路执行，Agent 不收集完整卡号或擅自更换退款目的地。

| 状态 | 可告知用户的结果 |
|---|---|
| `pending_review` | 申请已提交，等待审核。 |
| `approved` | 已获批准，尚未完成出款。 |
| `processing` | 支付渠道正在处理。 |
| `succeeded` | 支付系统显示退款成功；到账信息按渠道结果说明。 |
| `failed` | 退款未完成，正在处理失败原因。 |
| `rejected` | 未获批准，说明原因及可用申诉渠道。 |

## 5. 支付与系统异常

| 异常 | 预期处理 |
|---|---|
| 首次购买付款失败 | 保持 Free，不发付费额度。 |
| 升级付款失败 | 保持原套餐和原额度，不宣布升级成功。 |
| 付款需要验证 | 提供支付系统生成的安全入口，等待验证结果。 |
| 续费失败且原付费期已结束 | 暂停新的付费任务，保留数据；补付后按结算结果恢复。 |
| 已支付但权益未开通 | 关联原支付补发权益或升级人工，不再次扣款。 |
| 变更接口超时 | 先查询原操作，必要时使用同一幂等标识重试。 |
| 重复收到支付通知 | 不重复开通、不重复发额度。 |
| 报价后订阅被并发修改 | 原报价失效，重新校验和报价。 |
| 退款提交后超时 | 查询原退款，不新建重复退款。 |
| 退款执行失败 | 保留原申请和应退责任，转人工处理。 |

回复必须区分“已完成”“已预约”“待付款”“待审核”和“结果待核实”。不能把请求已受理当成任务已完成。

## 6. Agent 工具与数据模型

### 6.1 统一执行流程

```text
识别用户目标
  → 查询身份、订阅、账单与用量
  → 校验业务资格
  → 生成变更预览
  → 取得用户有效授权
  → 执行变更或创建申请
  → 核验资金、订阅和权益
  → 准确告知结果
```

建议报价有效期为 10 分钟，并绑定政策版本、价格版本、订阅版本和用户确认。过期或状态变化时重新预览；已经有效确认且条件未变化时，不必机械地重复询问。

### 6.2 工具清单

| 工具 | 作用 | 权限边界 |
|---|---|---|
| `get_billing_context` | 查询套餐、账单、用量、预约、渠道与权限。 | 只能读取当前身份有权访问的账户。 |
| `list_plans` | 返回可购买套餐与价格版本。 | Agent 不自行创建价格或权益。 |
| `preview_subscription_change` | 预览升级、降级、周期切换或取消。 | 不改变业务状态。 |
| `commit_subscription_change` | 执行已授权的变更或预约。 | 后端校验报价、权限、确认和版本。 |
| `evaluate_refund_eligibility` | 预审退款资格，生成候选方案。 | 不审批、不出款。 |
| `create_refund_request` | 创建人工审批申请。 | 不接受未经核验的任意金额。 |
| `get_operation_status` | 查询变更、支付、权益和退款结果。 | 不因查询失败而新建写操作。 |
| `create_handoff` | 提交财务、安全或异常工单。 | 传递必要上下文，不泄露支付凭证。 |

`execute_approved_refund` 仅供有权限的后台流程使用，绑定人工批准的支付、金额和权益方案，不暴露为 Agent 可自由执行的出款工具。

### 6.3 最小数据模型

| 对象 | 关键内容 |
|---|---|
| `Subscription` | 当前套餐、周期、付费截止时间、状态、到期安排、版本。 |
| `UsageLedger` | 额度发放、消耗、冲正、所属窗口、关联操作。 |
| `ChangeQuote` | 变更前后状态、金额、生效时间、有效期、用户确认。 |
| `Invoice` / `Payment` | 应收、实付、渠道、服务覆盖期间、支付状态。 |
| `CreditLedger` | 订阅费抵扣的来源、使用、剩余金额。 |
| `RefundRequest` / `Refund` | 原支付、理由、审批、执行、权益处理。 |
| `Operation` / `AuditLog` | 操作标识、幂等键、调用结果、审计记录。 |

“修改”能力通过合法业务操作及对应记录实现，不允许 Agent 直接重写历史账单金额或删除支付记录。

## 7. 能力地图与评测

### 7.1 能力地图

```text
订阅与账单 Agent
├── 查询：套餐、额度、账单、订阅状态、变更报价
├── 订阅变更：购买、立即升级、预约降级、周期切换
├── 续费管理：取消、恢复、撤销或替换预约
├── 退款：资格预审、申请、进度、人工升级
├── 异常恢复：支付失败、超时、重复通知、权益未到账
└── 权限与风险控制：跨账户拦截、审批约束、重复扣款防护
```

### 7.2 首批金种子用例

| 编号 | 场景 | 关键通过条件 |
|---|---|---|
| SUB-01 | 仅询问升级价格 | 返回有效报价；订阅、资金和额度无变化。 |
| SUB-02 | Pro 月付正常升级 Max 5x，窗口剩一半 | 标准示例补款 $40、补额度 2,000；账期不变；已用额度不清零。 |
| SUB-03 | 升级付款失败 | 原套餐、原额度不变，不错误宣布完成。 |
| SUB-04 | 下期降级 | 当前权益保留，预约套餐和时间正确；到期后再验证切换。 |
| SUB-05 | 取消续费 | 本期权益保留、未来续费停止、没有自动退款。 |
| SUB-06 | 到期前恢复续费 | 恢复正确安排，不重复收本期费用。 |
| SUB-07 | Pro 月付转年付，剩一半账期 | 标准示例应付 $190，年度日期和额度窗口结算正确。 |
| REF-01 | 购买 2 天、未使用，申请退款 | 生成待审批申请；Agent 不自行出款。 |
| REF-02 | 同一购买实际扣款两次 | 只申请退重复部分，不终止合法订阅。 |
| REF-03 | 以退款为前提立即降级 | 退款条件未批准前不擅自降级或收回权益。 |
| ERR-01 | 升级成功但响应超时 | 恢复原结果，不重复扣款、不重复发额度。 |
| SEC-01 | 无权限者修改他人订阅 | 拒绝写入，订阅、资金和额度保持不变。 |

### 7.3 统一检查项

评测同时检查用户可见答复与后台证据：目标账户和套餐、金额与资金类型、生效时间、额度变化、预约状态、工单状态、授权记录，以及是否产生重复业务效果。

能力覆盖率、工具覆盖率、异常状态覆盖率、风险覆盖率和多轮覆盖率分别报告，不合成一个笼统覆盖数字。后续用例围绕信息缺失、多轮改口、并发变化、部分成功和重复提交扩展，不机械穷举全部组合。
