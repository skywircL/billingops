# BillingOps v3.1：从 bad case 到可复核迭代

业务默认仍为 A / fixed。原 v2 与挑战 v1 结果保持不变。本次没有强化学习、全量框架替换或改写旧分数。

## 改了什么

1. 退款目标由真实用户输入与业务记录确定；客户不知道编号时继续读取，账号范围内必须确认唯一额外付款。多个目标、未读完或指定原付款时不代选。
2. B 提前提交且候选未读完时收到缺失账单反馈；反馈使用既有修复与模型调用预算。A 扫描所有候选，预算不足则安全退出。
3. 审批指纹绑定目标消歧证据，执行前重新确认推断目标；新歧义不发送退款，并清除旧提案/审批令牌。
4. 新增语义退差价标记并给予路由优先级；仍只转人工，不自动退差价。
5. 结论提示区分无法核实与否定资格；共享结论输入补入已查账户记录。缺失目标不再抹掉读过的证据。

## 新分支的4个B失败如何解释

- budget-incomplete：工具协议修复耗尽，安全升级但没有完成结构化收尾，真实运行失败。
- zero-duplicates-unknown：读完全部记录后没有发现重复，输出no_duplicate_found；gold只接受信息不足/升级，评分待校准。
- original-payment-selected：命名原付款不可退，代码拒绝代选；no_refund_due与gold的信息不足存在处置规范差异。
- unverifiable-target：正确业务终态，但本地drain超过60秒抛异常，保留失败。不能把自动infra标签当作外部故障证据，更不能排除B自身调用量造成的耗时。

两项评分争议、一个本地运行器期限问题、一个模型协议问题分开报告，未将它们事后合并成B12/12。完整存档重评分仍为A12/12、B8/12。

## 尚未解决
